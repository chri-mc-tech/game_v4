------------------
LOGICA PRINCIPALE
------------------

Appena un player apre il client viene generato un uuid casuale e salvato in un file di config
tutti i dati nei server sono collegati al uuid, cosi che un player puo cambiare nome senza problemi

Controlli importanti come password e crittografia farli lato server per evitare exploit il piu possibile
fare che quando un player si collega non viene fatto nulla dal server ma il client manda un pacchetto con uuid
viene creato il player con uuid come PK (parametro primario) e viene generata chiave privata server, chiave pubblica server
poi il client genera la chiave privata e pubblica del client e vengono scambiate le chiavi pubbliche
poi vengono generate le session key e dopo le encryption key sia su client che su server

Avendo gia l'uuid, il server controlla se è salvato nel db locale
se l'utente non esiste il server chiede la password per registrarsi e la salva nel db
senno chiede la pass di login e la confronta con quella salvata nel db
il server controlla l'hash col file dell'utente


---------------------
CODICI ERRORE CLIENT
---------------------

1 = general error
3 = unable to initialize libraries
4 = error creating config file
5 = error loading config
6 = error creating enet host
8 = uuid not valid


---------------------
CODICI ERRORE SERVER
---------------------

1 = general error
3 = unable to initialize libraries
4 = error creating config file
5 = error loading config
6 = error creating enet host


---------------------
CANALI
---------------------

0 = pacchetti iniziali (prima di Diffie Hellman) (non cifrati)
1 = pacchetti non cifrati (es: coordinate)
2 = pacchetti cifrati (es: hash password)
